# Drive Bot 触发与连续对话用例

本文列出当前支持的命令、自然语言请求和后续任务查询方式。群聊中每条消息都需要 @ Bot；私聊直接发送。示例中的资源 ID、标题和任务编号用于说明，实际使用时以 Bot 返回的结果为准。

## 使用前准备

- 普通聊天与自然语言工具需要可用的 `llm` 配置，模型接口需支持 OpenAI-compatible tools。
- `llm.tools.enabled` 默认 `true`；关闭后仍可使用明确命令，但普通聊天不再选择工具。
- 每日新闻默认使用腾讯新闻热点榜；动漫新闻需要在 `tasks.anime_news.file_path` 配置可读取的新闻文件。
- 更新代码或配置后重启 Bot，再进行试用。

完整配置见 [项目 README](../readme.md#配置) 和 [插件说明](../plugins/drive_bot/README.md)。

## 触发用例速查

明确命令由程序直接识别。自然语言示例由 LLM 判断意图并选择工具，不是固定关键词匹配；只是提到一个功能或关键词，不代表要求执行。

| 能力 | 明确命令 | 自然语言用例 | 预期操作 |
| --- | --- | --- | --- |
| JM 搜索 | `/jm 原神` | `搜索原神的本子`、`帮我搜索 JM，关键词是原神` | `jm_search`，展示最多 10 条结果及序号 |
| JM 下载 | `/jm 123456` | `下载 ID 为 123456 的本子`、搜索后说 `下载第二个` | `jm_download`，下载任务入队 |
| 每日新闻 | `/news`、`/dailynews`、整句 `每日新闻` | `今天有什么新闻吗`、`看看今日新闻` | `daily_news`，获取综合热点新闻并生成摘要 |
| 动漫新闻 | `/anime-news`、`/animenews`、整句 `动漫新闻` | `最近有什么动漫新闻`、`看看动漫资讯` | `anime_news`，发送已配置的动漫新闻内容 |
| 随机涩图 | `/setu` | `涩图`、`来张涩图` | `setu`，按空标签随机获取一张图片 |
| 带标签涩图 | `/setu 猫耳 蓝发` | `来张猫耳蓝发的涩图`、`来张猫耳的涩图` | `setu`，提取最多 3 个标签并创建图片任务 |
| 任务状态 | `/task`、`/task 42` | `完成了吗`、`刚才那个任务怎么样了`、`查一下任务 42` | `task_status`，查询数据库中的真实状态 |
| 帮助 | `/help`、`帮助`、`使用方法`、`help` | 使用左侧固定入口 | 直接返回使用说明 |
| 用户画像 | `/profile`、`/showUserProfile` | 使用左侧固定入口 | 展示当前用户画像 |
| 每日 AI 看点 | `/dailyai`、整句 `每日ai` | 暂未工具化，使用命令 | 读取本地论文数据并生成总结 |
| 热门论文 | `/trending`、整句 `热门论文` 或 `trending` | 暂未工具化，使用命令 | 获取近期热门 AI 论文摘要 |

中文别名需整句发送。例如 `每日新闻` 是直接入口，而 `我想聊聊每日新闻功能` 会进入模型判断，不应仅因包含“每日新闻”就创建任务。

## 搜索后选择下载

私聊示例；群聊中为每条“你”的消息加上 @ Bot。

```text
你：搜索原神的本子
Bot：1. [123456]: 标题 A
     2. [234567]: 标题 B
     可以用 /jm ID 下载，或告诉我“下载第二个”。
你：下载第二个
Bot：已收到，任务 #42 已加入队列。
     当前排队位置：……
     预计等待：……
你：刚才那个下载好了吗？
Bot：任务 #42：运行中。
```

“第二个”由程序映射到当前会话结果中的 ID，不由模型猜测。你也可以从 `/jm 原神` 开始搜索，再用自然语言选择结果。

没有有效搜索结果、结果已过期或序号越界时，不会创建下载任务。重新搜索失败或没有结果后，旧列表会被清除；重新搜索成功后，序号对应最新列表。

## 缺少参数时补充

```text
你：帮我搜索本子
Bot：你想搜索什么关键词？
你：原神
Bot：展示原神的搜索结果。
```

你可以补充关键词，也可以说 `不搜了，聊点别的` 或发送其他命令。Bot 不应把后续每条消息都当作搜索关键词。

下载请求缺少 ID 和序号时，也会询问目标。若模型或接口临时失败，待补参数仍保留，稍后可以再次补充。

## 每日新闻和动漫新闻

```text
你：今天有什么新闻吗？
Bot：每日新闻
     已收到，任务 #43 已加入队列。
Bot：发送新闻摘要及链接。
你：完成了吗？
Bot：任务 #43：成功。
```

```text
你：最近有什么动漫新闻？
Bot：动漫新闻
     已收到，任务 #44 已加入队列。
Bot：发送已配置的动漫新闻内容。
你：/task
Bot：任务 #44：成功。
```

工具入队不代表内容已经获取成功；服务实际执行后才更新任务状态。动漫新闻文件配置错误、读取失败或发送失败时，任务会标记为失败。

两个新闻工具都不接收主题或历史日期参数；动漫新闻内容来自配置文件，不会自动联网搜索。新闻正文和后台完成通知不会自动加入短期聊天历史，当前连续办事主要支持触发任务、选择资源和查询状态。

## 涩图请求

```text
你：涩图
Bot：涩图
     已收到，任务 #45 已加入队列。
Bot：获取并上传图片文件。
```

```text
你：来张猫耳蓝发的涩图
Bot：涩图
     已收到，任务 #46 已加入队列。
你：完成了吗？
Bot：任务 #46：排队中。
```

第二个示例期望模型提取 `猫耳`、`蓝发` 两个标签；你也可以发送 `/setu 猫耳 蓝发`，直接使用明确标签。

- `/setu`、`来张涩图` 未指定标签时随机获取。
- 命令中的标签按空格分隔，最多 3 个，例如 `/setu 猫耳 蓝发 女仆`。
- `/setu a b c d` 会被拒绝；工具参数超过 3 个标签、标签不是文字或标签为空，也不会入队。
- 每个图片任务获取一张图片，不支持用工具指定数量、文件路径或其他接收者。
- `这个涩图功能怎么用` 或 `我想讨论涩图标签` 属于讨论示例，不应仅因包含“涩图”就执行图片任务。

## 查询最近任务与指定任务

```text
你：/jm 123456
Bot：任务 #47 已加入队列。
你：今天有什么新闻吗？
Bot：任务 #48 已加入队列。
你：/task
Bot：查询任务 #48。
你：/task 47
Bot：查询任务 #47。
```

`/task` 和没有指定编号的状态工具默认查询当前会话最近提交的任务。要查询更早的任务，使用 Bot 返回的明确编号。

任务状态包括排队、运行、成功、失败、取消。排队状态提供位置和预计等待时间，当前不提供百分比进度，也没有取消任务入口。

只能查询当前会话中属于自己的任务。同一个用户在另一个群或私聊中，也不能用该入口查询原群的任务。

## 上下文与错误场景

| 场景 | 行为或处理方式 |
| --- | --- |
| 群聊消息未 @ Bot | 不处理；当前没有自动续聊或主动参与功能 |
| 临时状态 15 分钟未更新或 Bot 重启 | 搜索结果、待补参数和最近任务引用清空；重新搜索或使用 `/task 编号` |
| Bot 重启后的旧任务 | 任务记录仍在 SQLite 中；旧排队任务的完成通知可能因缺少内存事件而无法发送，使用编号查询 |
| 一个请求中模型返回多个工具调用 | 本次不执行任何工具，请拆成多条请求 |
| 工具参数含未知字段或无效类型 | 拒绝执行，重新描述或使用明确命令 |
| 同一 QQ 消息重复投递 | 在去重窗口内只处理一次；主动发送的新消息仍可能创建新任务 |
| 模型接口不支持 tools 或决策超时 | 本次不追加模型重试，改用 `/jm`、`/news`、`/anime-news`、`/setu`、`/task` 等明确命令 |

## 调用次数与日志

明确命令的路由不调用 LLM；启用工具时，一条自然语言消息最多一次决策请求。入队回复和状态查询结果由程序生成，不再额外调用模型润色。

每日新闻生成摘要时仍会使用已有 LLM 摘要服务，因此自然语言新闻请求通常包含一次决策请求和一次摘要请求；`/news` 可以省去决策请求。动漫新闻读取文件，图片获取与上传本身不调用 LLM。

DeepSeek V4（`deepseek-v4-*`，以及 `deepseek-flash` / `deepseek-pro`）的工具决策请求显式关闭思考模式。当前会话保存精简文字摘要，不保存或回传思维链；非思考模式可避免后续轮次缺少 `reasoning_content` 的兼容性错误，并减少决策 token 开销。此设置只作用于工具决策服务。

成功解析模型响应后，可以看到类似日志：

```text
LLM tool decision: llm_requests=1 tool_calls=0 prompt_tokens=... completion_tokens=...
LLM tool decision: llm_requests=1 tool_calls=1 prompt_tokens=... completion_tokens=...
Queued news tool: tool=daily_news task_id=43
Queued news tool: tool=anime_news task_id=44
Queued image tool: tool=setu task_id=45
```

`tool_calls` 是模型返回的工具调用数量，不等于已经执行的数量。实际入队日志和任务编号才能确认新闻或图片任务已经创建；完成与否通过任务状态确认。

决策失败时日志记录异常类型、HTTP 状态和固定错误分类，例如：

```text
LLM 工具决策失败: error_type=BadRequestError status=400 reason=reasoning_history_required
```

日志不输出原始异常正文、API Key 或对话内容；失败不自动重试，也不执行工具。`reasoning_history_required` 表示异常正文提到 `reasoning_content`，其他常见分类包括 `timeout`、`authentication`、`rate_limit`、`invalid_request`、`upstream_error`、`empty_response` 和 `unknown`。
